## Evaluation rules for future runs

- Use only `gpt-6-luna` with `reasoning.effort=low` or `high`; do not substitute `max` for `high`.
- Keep the user prompt to command, purpose, and error. Do not add incident history, operator assumptions, preferred fixes, or constraints that make the true repair unavailable.
- Reset the lab between calls; each effort gets a fresh conversation and no prior-trial content.
- Score separately: root-cause diagnosis, first mutation, final answer, and end-to-end verification. An ineffective first repair followed by a correct diagnosis is not the same as a persistent false diagnosis.
- Preserve each API trace and its prompt-cache summary under `astra/`, but do not count HTTP errors as model trials.
